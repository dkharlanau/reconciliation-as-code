Why it exists

Migration reconciliation often ends up split across temporary SQL, spreadsheets, screenshots, and sign-off notes. This project keeps the control logic and evidence contract versioned and repeatable.

01

Codify the control

Define keys, scope, mappings, tolerances, hierarchy, identity changes, accepted exceptions, and materiality explicitly.

02

Run at useful scale

Use CSV or Excel for straightforward work, DuckDB for supported CSV/Parquet controls, and runtime connection references for SQLite or PostgreSQL.

03

Retain provenance

Canonical evidence records specification and input fingerprints. Optional bundles add offline HTML, XLSX, and CSV detail files with privacy controls.

A deterministic operating loop

Profile unfamiliar data, validate the specification, run the requested controls, and review evidence before using it for a cutover or release decision.

Typical commands

rac inspect examples/customer-migration/legacy.csv --json
rac validate examples/customer-migration/reconciliation.yaml
rac run examples/customer-migration/reconciliation.yaml \
  --bundle build/evidence-bundle \
  --no-fail-on-diff

Beyond a single comparison

rac pipeline localizes the first stage where drift appears. rac diff compares retained evidence from two rehearsals without requiring the original data.

The tool evaluates outcomes. It does not move data, infer business acceptance, or authorize access to source systems.

Agent entry point

Automation must preserve the judgment boundary.

The manifest describes the real CLI entry points and a conservative loop for agents. Tolerances, crosswalks, exceptions, and acceptance decisions remain explicit human-governed inputs.

Open agent manifest

Reconciliation should be reproducible, not remembered.
