Turn migration and transformation checks into reusable rulepacks that say what was compared, what passed, what failed, what was waived, and which evidence supports the decision.

A green status is useful only when a reviewer can reconstruct why it is green.

Why it exists

Project reconciliation is often a collection of one-off SQL, spreadsheets, screenshots, and manual sign-offs. That makes repeatability and auditability harder exactly when data risk is highest.

01

Codify the check

Rulepacks make comparison logic reusable across runs, environments, migration waves, and teams.

02

Separate policy from data

Profiles, scoped suites, waivers, and release policy make acceptance logic explicit.

03

Preserve provenance

Evidence bundles, integrity checks, signatures, trends, and lineage let teams prove what they evaluated.

From raw comparison to release decision

The framework supports simple count checks and richer row, pair, multi-source, and CDC assurance without changing the basic operating model.

Typical loop

rac validate <rulepack.yaml>
rac inspect <rulepack.yaml>
rac run <rulepack.yaml>
# keep structured automation output
# verify evidence / trust before release use

What the result carries

Rule results, scopes, tolerances, waivers, provenance, integrity metadata, and evidence can travel together instead of being reconstructed from a test folder later.

Not a data migration engine. It evaluates and evidences outcomes; it does not move or transform the source data itself.

Where it connects

Reconciliation becomes stronger when it can reference the transformation contract and feed assurance state into cutover or project evidence.

Agent entry point

Automation should not hide the judgment.

Agents can validate, run, and summarize rulepacks, but policy, waivers, and trust remain explicit inputs. Structured stdout and separate diagnostics keep automation dependable.

DISCOVER

Read capabilities

docs/agent-manifest.json tells an agent what it can safely evaluate.

RUN

Use deterministic checks

Validate first, execute the requested rulepack, and preserve machine-readable results.

TRUST

Verify the evidence

Do not reduce a release decision to a boolean without the policy and evidence behind it.

Reconciliation should be reproducible, not remembered.

Write the acceptance logic once, run it repeatedly, and keep enough evidence for another person to challenge the result.
